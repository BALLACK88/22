# Git, GitHub, GitLab 기초

> 질문: github, gitlab 등이 있는데 잘 몰라. git이 뭐야?
> 정리일: 2026-09-24

## 1. Git이 뭐야?

**Git은 파일의 변경 이력을 기록하는 프로그램이다.**

이런 파일 관리를 해본 적이 있다면 Git이 필요한 이유를 알 수 있다.

```
기획서_v1.pptx
기획서_v2.pptx
기획서_v2_수정.pptx
기획서_최종.pptx
기획서_최종_진짜최종.pptx
```

Git을 쓰면 파일은 **하나만** 두고, 저장할 때마다 이력이 남는다.

- **누가, 언제, 무엇을, 왜** 바꿨는지 기록된다.
- 언제든 **예전 버전으로 되돌릴 수** 있다.
- 여러 사람이 **동시에 작업하고 합칠 수** 있다.

## 2. 꼭 알아둘 용어 4개

| 용어 | 뜻 | 기획 업무에 비유하면 |
|---|---|---|
| **커밋 (commit)** | 변경 내용을 이력으로 저장 | "v3 저장, 메모: 매뉴얼 연결 기능 추가" |
| **브랜치 (branch)** | 원본을 건드리지 않는 작업용 사본 | 원본을 복사해서 "B안"을 따로 만들어 보기 |
| **병합 (merge)** | 브랜치 작업을 원본에 합치기 | B안이 채택돼서 원본에 반영 |
| **푸시 (push)** | 내 컴퓨터의 이력을 서버에 올리기 | 공유 폴더에 업로드 |

## 3. GitHub, GitLab은?

- **Git** = 이력 관리 **프로그램** (도구 자체)
- **GitHub / GitLab** = Git 저장소를 올려두는 **온라인 서비스**

비유: **Git은 엑셀, GitHub·GitLab은 구글 드라이브·셰어포인트** 같은 관계다. 기능은 비슷하고 회사마다 쓰는 곳이 다르다.

| | GitHub | GitLab |
|---|---|---|
| 특징 | 세계 최대 규모, 오픈소스 중심 | 회사 내부 서버에 직접 설치해 쓰는 경우가 많음 |
| 많이 쓰는 곳 | 개인, 스타트업, 오픈소스 | 보안을 중시하는 기업 (자동차·제조업에서 흔함) |

### PR / MR

- GitHub는 **PR(Pull Request)**, GitLab은 **MR(Merge Request)** 이라고 부른다. 둘은 같은 기능이다.
- 뜻: "제가 이렇게 바꿨는데 검토 후 합쳐주세요"라는 **결재 요청**
- 개발자 회의에서 "PR 올렸어요", "MR 리뷰해주세요"라는 말이 이 뜻이다.

## 4. 내 저장소로 보는 예시

- `ballack88/22` = GitHub에 있는 내 저장소
- Claude가 한 일: `CLAUDE.md` 작성 → **커밋** → `claude/new-session-oxedd2` **브랜치**에 **푸시**
- 아직 **main에 병합되지 않은** 상태다. PR을 만들어 합치면 원본에 반영된다.

## 5. 한 줄 요약

> **Git = 변경 이력 관리 도구, GitHub/GitLab = 그 이력을 올려두고 함께 검토하는 온라인 공간, PR/MR = 합쳐달라는 결재 요청**
