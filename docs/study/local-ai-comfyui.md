## 1. 내 PC 사양 이해하기

### CPU: Ryzen 7 9800X3D
- 8코어 16스레드, 3D V-Cache(L3 96MB)를 얹은 **게임 최강급 CPU**다.
- 캐시를 코어 **아래**로 옮겨서 클럭 손해가 거의 없다. 그래서 일반 작업 성능도 같은 8코어인 9700X 수준 이상이다.
- 약점: 렌더링이나 인코딩처럼 **코어를 전부 쓰는 작업**은 16코어(9950X 등)보다 느리다.
- 문서, 회의, Figma, Python 공부에는 **차고 넘친다.**

### GPU: Radeon RX 9070 XT
- **VRAM 16GB**, RDNA4 구조
- AI 작업에서는 CPU보다 **GPU와 VRAM이 훨씬 중요**하다.

### 한 줄 요약
> 작업 환경에서 체감되는 건 CPU보다 **RAM 32GB 이상 + NVMe SSD**, AI에서는 **VRAM**이다.

## 2. 로컬 AI 도구 한눈에 보기

| 도구 | 용도 | 가격 |
|---|---|---|
| **LM Studio** | 글 AI (대화, 요약). **이미지 생성은 못 함** | 무료 |
| **Ollama** | 글 AI (명령어 방식) | 무료, 오픈소스 |
| **Amuse** | 이미지 AI (AMD 협력 앱, 쉬움) | 무료 |
| **ComfyUI** | 이미지·영상·3D·오디오·LLM (노드 방식) | 무료, 오픈소스 (GPL-3.0) |
| **ROCm** | AMD GPU용 AI 드라이버 (엔비디아 CUDA에 해당) | 무료, 오픈소스 |

### 무료와 유료의 경계
- **내 PC에서 돌리면** 프로그램도 모델도 대부분 무료다. 드는 건 전기요금뿐이다.
- **유료인 것**: 클라우드 서비스 (Comfy Cloud, ChatGPT Plus, Midjourney 등), ComfyUI 안의 **API / 파트너 노드**
- ComfyUI에서 **👑 왕관, "REQUIRES CREDITS", "API", "Partner"** 표시가 있으면 유료다.
- 모델마다 **라이선스**가 다르다. 개인 공부는 거의 문제없지만, **상업적 이용**은 모델 페이지에서 확인해야 한다.

### ROCm은 따로 설치해야 하나?
- LM Studio, Ollama처럼 **AI를 사용만** 할 때는 필요 없다. (Vulkan 또는 내장 ROCm 사용)
- PyTorch로 **직접 개발·학습**할 때 필요하다.
- RX 9070 XT는 **ROCm 7.2**부터 윈도우에서 제대로 지원되고, AMD Adrenalin 드라이버에 ComfyUI 통합 설치도 생겼다.

## 3. ComfyUI 설치 과정

Comfy Desktop을 설치하면서 고른 것들과 이유.

| 화면 | 선택 | 이유 |
|---|---|---|
| How do you want to run Comfy? | **Local** | Cloud는 체험만 무료이고 이후 유료. 내 GPU가 있으니 Local |
| Express Install | **체크 안 함** | GPU 종류와 설치 경로를 직접 고르기 위해 |
| EULA 동의 | 체크 | 필수 |
| Beta features | **체크 해제** | AMD 환경은 안정 버전이 좋음 |
| Release / Version | Stable (Recommended) | 안정 버전 |
| Hardware | **AMD** | 자동으로 RX 9070 XT를 인식 |
| Install location | 기본값 또는 **여유 큰 SSD** | 경로에 **한글·띄어쓰기 없이** |
| Starter workflow | Image 탭의 모델 | 영상(Video)은 처음 하기엔 무겁거나 유료 |

### 첫 화면(대시보드)의 인스턴스
| 카드 | 뜻 |
|---|---|
| **ComfyUI** (💻) | 내 PC에 설치한 것 → 이걸 쓴다 |
| **Comfy Cloud** (☁️) | 회사 서버에서 돌리는 것 → 유료 |
| New Instance | 새로 하나 더 설치 (문제가 생겼을 때 깨끗하게 다시 만들기) |

### 메뉴 위치 헷갈리지 않기
- 맨 위 **☰** = Comfy **Desktop 앱** 메뉴 (대시보드, 인스턴스, 벤치마크)
- 그 아래 **`C⌄` 로고** = **ComfyUI 작업 화면** 메뉴 → 여기서 **템플릿 찾아보기**

## 4. 확장 프로그램(커스텀 노드) 주의사항

> **보이는 대로 다 설치하면 안 된다. "설치해놓고 안 쓰면 되는" 게 아니다.**

1. **설치만 해도 실행된다.** 커스텀 노드는 ComfyUI가 켜질 때마다 자동 실행되는 Python 코드다. 실제로 계정 정보를 훔치는 **악성 노드**가 발견된 사례도 있다.
2. **AMD 환경이 망가질 수 있다.** 많은 노드가 엔비디아 기준이라, 설치 과정에서 AMD용 PyTorch(ROCm)가 **엔비디아용으로 바뀌어** GPU를 못 쓰게 될 수 있다.
3. **충돌하고 느려진다.**

### 원칙
- 지금은 **필수 확장이 없다.** 기본 템플릿은 기본 기능만으로 돌아간다.
- ComfyUI-Manager(노드 관리 도구)는 Desktop에 **이미 들어 있다.**
- 특정 워크플로우가 요구할 때 **그것만** 설치한다. 설치 전에 먼저 확인받기.
- 이미 망가졌으면 **New Instance**로 깨끗하게 새로 만드는 게 가장 빠르다. (모델은 공유 폴더라 다시 안 받아도 됨)

## 5. VRAM과 모델 용량

### 저장 용량 ≠ VRAM, 하지만 관련 있다
- 템플릿 카드에 적힌 용량(예: ~19GB)은 **다운로드 용량**, 즉 **SSD 공간**이다.
- 이미지를 만들 때 모델이 **SSD → RAM → VRAM**으로 올라간다. 그래서 **파일이 크면 VRAM도 많이 필요**하다.

### 모델은 여러 부품의 합이다 (Z-Image-Turbo 예)
| 부품 | 역할 | 크기 |
|---|---|---|
| 텍스트 인코더 (`qwen_3_4b`) | 프롬프트(글)를 이해 | 약 8GB |
| 이미지 모델 (`z_image_turbo_bf16`) | 실제로 그림을 그림 | 약 12GB |
| VAE (`ae`) | 결과를 이미지 파일로 변환 | 작음 |

- ComfyUI는 부품을 **순서대로 올렸다 내렸다** 한다. 모자라면 RAM으로 잠시 빼둔다.
- 하지만 RAM은 VRAM보다 **훨씬 느리다.** 합계가 VRAM을 크게 넘으면 **느려지거나 멈춘다.**

### VRAM 관리 원칙
- **VRAM 16GB는 한 번에 한 작업.** ComfyUI와 LM Studio를 동시에 돌리지 않는다.
- 모델(워크플로우)을 바꿀 때는 **ComfyUI를 재시작**해서 VRAM을 비운다. 탭만 바꾸면 이전 모델이 VRAM에 남아 있을 수 있다.
- 게임, 영상 재생 등 GPU를 쓰는 다른 프로그램은 끈다.

## 6. 양자화: bf16 vs Int8

같은 모델인데 **숫자를 얼마나 정밀하게 저장했느냐**만 다르다. 이걸 **양자화(Quantization)** 라고 한다.

> 비유: **bf16 = 카메라 RAW 원본**, **Int8 = 고화질 JPEG**

| | bf16 (원본) | **Int8** |
|---|---|---|
| 숫자 하나 저장 크기 | 16비트 | 8비트 (절반) |
| 용량 | 큼 | 약 절반 |
| 품질 | 기준 | 거의 같음 |
| VRAM 16GB에서 | 부품과 합치면 초과 → 느려지거나 멈춤 | 여유 있게 들어감 |

### 버전 이름 정리
| 이름 | 비트 | 용량 | 품질 |
|---|---|---|---|
| fp32 | 32 | 가장 큼 | 원본 |
| bf16 / fp16 | 16 | 큼 | 거의 원본 (기본 배포형) |
| **fp8 / int8** | 8 | 절반 | 거의 같음 ⭐ VRAM 16GB에 추천 |
| GGUF Q4 등 | 4 | 1/4 | 약간 떨어짐 (VRAM 적은 카드용) |

## 7. 문제 해결: 로그와 작업 관리자 읽기

### 로그에서 볼 것
- 로그는 작업 화면 왼쪽 아래 **`>_` 아이콘**으로 연다.

| 로그 내용 | 뜻 |
|---|---|
| `load device: cuda:0` | GPU를 쓰고 있음. AMD도 호환 때문에 cuda라는 이름을 쓴다. **단, 어느 GPU인지는 아래 두 줄로 확인해야 한다** |
| `AMD arch: gfx1201` / `Device: ... RX 9070 XT` | ✅ **RX 9070 XT**를 쓰는 중 |
| `AMD arch: gfx1036` / `Device: ... AMD Radeon(TM) Graphics` | ❌ **CPU 내장 그래픽**을 쓰는 중 (매우 느림) |
| `mat1 and mat2 shapes cannot be multiplied` | **서로 맞지 않는 모델 파일**을 섞어서 고름 (예: 이미지 모델과 텍스트 인코더 짝이 안 맞음) |
| `... Staged` | 모델을 VRAM에 올릴 준비 |
| `0/8 ... Model Initializing` | 첫 단계 시작 직전. **첫 실행은 몇 분 걸릴 수 있음** |
| `2/8 [01:30<04:30, 45.0s/it]` | 8단계 중 2단계 진행, 한 단계에 45초 |
| `Prompt executed in ○○ seconds` | 완료. 걸린 시간 |
| `[ERROR] ... not in list` | 워크플로우가 찾는 **모델 파일이 없음** |

### 첫 실행은 왜 느린가
- 모델을 SSD → RAM → VRAM으로 옮기고, AMD GPU용 계산 코드를 **처음 한 번 준비(컴파일)** 하기 때문이다.
- 두 번째부터는 빨라진다. ComfyUI를 **켜둔 채로** 계속 쓰면 더 빠르다.
- 첫 실행이라도 **10분 넘게 0%면 비정상**이다.

### 작업 관리자 GPU 그래프 읽기
| 상태 | 뜻 |
|---|---|
| 전용 GPU 메모리 **16GB 꽉 참** + Compute **0%** | VRAM 부족으로 **멈춤** → 취소, 재시작, Int8로 변경 |
| 공유 GPU 메모리가 올라감 | VRAM이 모자라서 RAM을 빌려 쓰는 중 (느림) |

- 작업 관리자는 AMD의 AI 계산(ROCm/HIP)을 **제대로 표시하지 못할 때가 많다.**
- 더 정확하게 보려면 **AMD 성능 오버레이 (Ctrl + Shift + O)** 에서 GPU 사용률과 전력(W)을 본다.
- ⚠️ 작업 관리자 그래프만으로는 **어느 GPU를 쓰는지 판단하면 안 된다.** 반드시 로그의 `AMD arch`와 `Device` 줄을 확인한다.

### 실제로 겪은 일: 내장 그래픽으로 돌고 있었다
- 9800X3D에는 **CPU 내장 그래픽**(AMD Radeon(TM) Graphics, gfx1036)이 있다.
- 윈도우에서 ComfyUI는 **GPU 하나만** 쓰는데, 내장 그래픽이 첫 번째로 잡혀서 RX 9070 XT 대신 그걸 썼다.
- 로그에 `Total VRAM 37109 MB`처럼 **실제 VRAM(16GB)보다 큰 값**이 나오면, 시스템 RAM을 빌려 쓰는 내장 그래픽이라는 신호다.
- 해결: **장치 관리자 → 디스플레이 어댑터 → AMD Radeon(TM) Graphics → 디바이스 사용 안 함** 후 ComfyUI 재시작
  - 모니터 케이블은 **메인보드가 아니라 그래픽카드**에 꽂혀 있어야 한다.
  - 되돌리려면 같은 곳에서 **디바이스 사용**을 누르면 된다.
- 결과: Z-Image-Turbo 1024×1024 8단계가 **3분 넘게 멈추던 것 → 20초 이내**로 해결

### 멈췄을 때 해결 순서
1. 빨간 **✕**로 취소
2. **ComfyUI 재시작** (VRAM 비우기)
3. **Int8 / fp8** 같은 가벼운 버전으로 변경
4. 그래도 안 되면 해상도를 **768**로 낮추기

## 8. 모델 파일 관리와 삭제

### 모델 저장 위치
```
%LOCALAPPDATA%\Comfy-Desktop\ComfyUI-Shared\models
```
- 파일 탐색기 주소창에 붙여넣으면 열린다.
- **Shared(공유)** 폴더라서 인스턴스를 새로 만들어도 모델을 같이 쓴다.

| 폴더 | 들어 있는 것 |
|---|---|
| `checkpoints` | 부품이 하나로 합쳐진 모델 (예: SDXL Turbo) |
| `diffusion_models` | 이미지 모델 본체 (예: Z-Image-Turbo) |
| `text_encoders` | 프롬프트 이해 부품 |
| `vae` | 이미지 변환 부품 |

### 삭제 방법
1. **ComfyUI 종료** (사용 중인 파일은 안 지워짐)
2. 위 경로로 이동해서 폴더 안의 **파일만** 선택
3. **Shift + Delete** (그냥 Delete는 휴지통으로 가서 용량이 안 줄어듦)

### 삭제 원칙
- **새 버전이 잘 되는 걸 확인한 뒤** 옛 버전을 지운다.
- 여러 모델이 **같이 쓰는 부품**(텍스트 인코더, VAE)은 지우지 않는다.
- 이름을 모르는 파일은 확인하고 지운다.
- `models` 안의 **폴더 자체는 지우지 않는다.**

## 9. ComfyUI 화면과 노드 구조

### 기본 흐름 (SDXL Turbo 예)
```
체크포인트 로드 → CLIP 텍스트 인코딩 → KSampler → VAE 디코드 → 이미지 저장
  (모델 준비)        (글 이해)          (그림)     (이미지로 변환)  (파일 저장)
```
- 노드 사이의 **색깔 선** = 데이터가 흐르는 길. **같은 색끼리만** 연결된다.
- 실행 중인 노드는 **초록 테두리**로 표시된다.

### 체크포인트 로드 노드
| 출력 | 역할 |
|---|---|
| 🟣 모델 | 그림을 그리는 본체 → KSampler로 |
| 🟡 CLIP | 프롬프트 번역 → CLIP 텍스트 인코딩으로 |
| 🔴 VAE | 결과를 이미지로 변환 → VAE 디코드로 |

- Z-Image-Turbo는 이 세 부품이 **파일 3개로 나뉘어** 있어서 워크플로우 모양이 다르다.
- 그래서 모델을 바꿀 때 **파일 이름만 바꾸면 안 되고**, 그 모델용 **템플릿을 새로 연다.**

### 긍정 / 부정 프롬프트
| 칸 | 뜻 |
|---|---|
| 위쪽 (긍정) | **그려줘** |
| 아래쪽 (부정) | **그리지 마** (예: `text, watermark`) |

- SDXL Turbo는 **cfg 1.0**이라 부정 프롬프트가 거의 효과가 없다.

### 주요 설정값
| 설정 | 뜻 |
|---|---|
| width / height | 이미지 크기 |
| **seed** | 랜덤 번호. **같은 seed + 같은 프롬프트 = 같은 그림** |
| steps | 그리는 단계 수 (Turbo 모델은 적어도 됨) |
| control after generate | `randomize`: 매번 seed 변경 / **`fixed`: seed 고정** |

### 모델별 기본 설정
| | SDXL Turbo | Z-Image-Turbo |
|---|---|---|
| 해상도 | 512×512 | 1024×1024 |
| steps | 1~4 | 8 |
| 프롬프트 방식 | 단어 나열 | 자연스러운 문장 |
| 속도 | 매우 빠름 | 보통 |
| 품질 | 보통 | 좋음 |

## 10. 프롬프트 작성법

### 기본 구조
> **누가/무엇이 + 배경 + 빛 + 색감 + 구도**

예시 (Z-Image-Turbo 기본 프롬프트):
```
Latina female with thick wavy hair, harbor boats and pastel houses behind.
Breezy seaside light, warm tones, cinematic close-up.
```
(숱 많은 웨이브 머리의 라틴계 여성, 뒤로 항구의 배와 파스텔톤 집들. 산들바람 부는 바닷가의 빛, 따뜻한 색감, 영화 같은 클로즈업)

### 모델에 따라 쓰는 방식이 다르다
| 모델 | 글 이해 부품 | 잘 맞는 방식 |
|---|---|---|
| SDXL 계열 | CLIP | **키워드 나열**: `glass bottle cute fox snow HDR sunset` |
| Z-Image-Turbo | Qwen3 언어 모델 | **장면을 설명하는 문장** |

### 실습 1: 요소가 빠지는 문제
- 프롬프트: `beautiful landscape scenery glass bottle with a galaxy inside cute fennec fox snow HDR sunset`
- 결과: 여우, 병, 눈, 노을은 나왔지만 **은하가 거의 빠짐**
- 이유: 키워드가 많으면 모델이 일부를 덜 중요하게 처리한다.

### 강조 문법
```
(galaxy inside:1.4)
```
- `(단어:숫자)` = 그 단어를 숫자만큼 강조
- 1.2~1.5가 적당. 너무 높으면 그림이 깨진다.

### 실습 2: seed 고정하고 단어만 바꾸기
- `cute fennec fox` → `cute kitten`, seed는 `fixed`
- 결과: **병, 노을, 배경 구도는 거의 그대로**이고 동물만 고양이로 바뀜
- 교훈: **seed 고정 + 단어 하나 변경 = 원하는 부분만 바꾸기**

### 효과가 약한 단어
- `Canon EOS R5`, `award-winning photography` 같은 말은 효과가 약한 편이다.
- `85mm lens`, `cinematic depth of field`(배경 흐림), `film grain`, `detailed skin texture`(AI 느낌 줄이기)는 효과가 있다.

## 11. 이미지를 참고해서 그리기

| 방법 | 설명 | 난이도 |
|---|---|---|
| **img2img** | 내 이미지를 밑그림 삼아 새로 그림 | ⭐ 쉬움 |

### img2img의 핵심: denoise
| denoise | 결과 |
|---|---|
| 0.3 | 원본과 거의 같고 느낌만 바뀜 |
| **0.5~0.6** | 구도 유지 + 스타일 변경 ⭐ 시작값 |
| 0.8 이상 | 원본은 참고 수준 |

## 12. 템플릿, 노드 그래프, 앱

| 용어 | 뜻 | 비유 |
|---|---|---|
| **템플릿** | 미리 만들어진 워크플로우 예제 | PPT 디자인 템플릿 |
| **노드 그래프** | 노드와 선이 전부 보이는 설계도 화면 | 수식이 다 보이는 엑셀 시트 |
| **앱** | 입력 칸과 실행 버튼만 보이는 간단한 화면 | 수식은 숨기고 입력 칸만 남긴 양식 |
| **앱 만들기** | 내 워크플로우에서 필요한 칸만 골라 앱으로 바꾸기 | 동료가 쓰기 쉬운 도구 만들기 |

> 기획자 관점: **노드 그래프 = 개발자가 보는 내부 설계**, **앱 = 사용자(정비사)가 보는 UI**.
> 복잡한 기능을 필요한 것만 보이게 정리하는 것, 지금 하는 기획 업무와 같은 생각이다.

### "노드 기초" 카테고리 (모델 없이 연습 가능)
| 템플릿 | 배우는 것 |
|---|---|
| **이미지 스티치 2x2 그리드** ⭐ | 이미지 4장을 한 장으로 → 시안 비교 자료 |
| 마스크 작업, 결합 및 합성 | 이미지 일부 선택·합치기 (인페인팅 기초) |
| 색상 조정 청사진 쇼케이스 | 밝기, 대비, 색감 보정 |
| 내장 데이터 유형 변환 예제 | 선 색깔(데이터 종류)이 다른 이유 |
| 노드 전환 | 조건 분기 (엑셀의 IF 같은 것) |

## 14. 오늘의 생각

> "하루하루 이렇게 빨리 변하는데 AI 전문가라는 게 말이 안 되겠다."

| 금방 바뀌는 것 (외울 필요 없음) | 오래 남는 것 (진짜 실력) |
|---|---|
| 어떤 모델이 최신인지 | VRAM, 용량, 양자화 같은 기본 원리 |
| 버튼 위치, 메뉴 이름 | 로그를 읽고 원인을 찾는 능력 |
| 모델 이름 | 이름 규칙을 보고 고르는 기준 |
| 추천 설정값 | 작게 테스트하고 늘려가는 습관 |

- AI 도구만 아는 사람은 많아진다.
- **자동차 진단 도메인 + AI를 적용할 줄 아는 기획자**는 드물고, 오래 가치 있다.
- 경쟁력은 "최신 모델을 다 아는 것"이 아니라 **"내 분야의 문제에 어떤 AI를 붙일지 판단하는 능력"** 에서 나온다.
